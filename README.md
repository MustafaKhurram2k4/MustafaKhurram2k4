10 — ENGINEERING PRINCIPLES

<details>
<summary><b>01 — Clarity over cleverness</b></summary>

<br>

If another developer cannot understand it, it probably isn't finished.

</details>

<details>
<summary><b>02 — Useful over impressive</b></summary>

<br>

A flashy feature that solves nothing is still noise.

</details>

<details>
<summary><b>03 — Smooth over complicated</b></summary>

<br>

Good software should feel obvious to the person using it.

</details>

<details>
<summary><b>04 — Build → observe → improve</b></summary>

<br>

The first version is allowed to be imperfect. The next version shouldn't be.
